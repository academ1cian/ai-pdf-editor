# Iterative PDF editing release

The browser keeps an immutable uploaded source, an approved document revision and one pending transaction. Text, layout, uploaded images, exact local logo lettering and optional image AI converge on candidate PDF bytes in the same PDF worker. Approval commits and downloads those exact bytes; a document Undo restores the previous approved bytes. Removing a request is a separate operation on the pending transaction.

## Conversation

Requests accumulate against the approved base. Stable source target IDs replace conflicting pending edits instead of duplicating them. References to wording introduced in pending text are mapped back to the original target. Editing an earlier request replaces it and removes later dependent turns after successful validation. Failed interpretation, fitting or provider calls preserve the last valid preview and display that the newest request was not applied. Individual changes can be adjusted or removed without AI. Manual image/text refinements also record transaction snapshots for conversational Undo.

The local English/Russian planner supports literal replacements, coordinated invoice changes and explicit primary-charge overrides. Decimal arithmetic uses BigInt fixed precision. An explicit charge correction retains the pending rate and computes the total from the updated charges and preserved fees; it does not force rate times quantity. Locally supported requests run locally even with cloud consent checked. Broader consented Groq requests include bounded document blocks and a compact pending summary. Neither PDFs nor document conversation state are stored on the server.

## Text and layout

The engine prefers original operands for equal-advance numeric substitutions. Verified whole text operands can be removed while preserving their text advance, then reconstructed without redaction side effects. Other selections use real redaction followed by insertion and the same integrity checks.

Fitting measures clear space on both sides using glyphs, image instances and vector borders. A longer heading can expand left while keeping its original right edge and its gap to the adjacent number. Longer paragraphs and cells wrap into measured clear space; type adjustments are bounded to 80% of the original size with an 8 pt floor (already-small source type is preserved when it fits). Connected paragraph lines can move coherently when their fonts, alignment and spacing identify one section and clear destination space is available. The explicit plan includes each moved source line, destination and permitted regions before mutation.

Real text transforms retain vertical point size and horizontal scaling. This avoids the subtle shrink introduced by treating MuPDF's geometric-mean size as the original vertical font size. Where the original font cannot be reused or lacks characters, the engine embeds redistributable Noto Sans in the appropriate regular/bold/italic style. Public fixtures cover full and subset embedded fonts and Cyrillic source/replacement text, including another edit after approval.

Arbitrary table-row reconstruction, complex mixed-style sections, rotated/clipped text, forms, signatures and pagination remain bounded support limits. An unsupported edit preserves the previous draft and explains the limit. Complete text is never silently truncated.

## Images and exact wordmarks

Image selection identifies a specific `Do` occurrence and its nested form-resource path, cumulative transformation matrix, dimensions and clipping. Replacement copies resources and content streams along only that occurrence's path. Other uses of a shared image stay unchanged. New drawing commands remain at the original drawing-order location and inside the existing clipping state. Moving/resize controls reject clipped or rotated instances and collisions with selectable text; uploaded replacements preserve aspect ratio. PNG alpha is retained. Redundant all-opaque alpha is removed without changing RGB samples.

Uploads accept bounded PNG/JPEG and a strict SVG element/attribute allowlist. SVG scripts, foreign content, external references, styles, entities and unsupported elements are rejected before rendering. Raster headers and SVG dimensions are checked before decoding. Safe SVG artwork is rasterized at up to four times its supplied dimensions within a 16-megapixel cap, preserving alpha; the whole PDF is never rasterized.

For exact logo text, bundled local Tesseract locates the wordmark in the selected bitmap. The original image bytes are recognized directly. A small unique OCR error may locate stylized lettering; OCR never supplies replacement spelling. The actual old bitmap pixels and antialiasing are erased on a verified uniform background, and deterministic exact lettering is placed in measured clear space. Every decoded pixel outside the planned wordmark region must match the source exactly. Complex backgrounds or ambiguous locations require an uploaded replacement. Vector/outlined artwork is not treated as selectable PDF text or as a bitmap image.

JPEG decoder downsampling differs from lossless-image resampling at small display scales. Before editing a wordmark, validation establishes the rendering of an unchanged lossless image reference and verifies that normalization changes no unrelated page region or page feature. Candidate comparison then uses the narrow wordmark region against that frozen reference. This does not enlarge the wordmark mask after seeing damage. Independent checks also compare source and exported decoded image pixels outside the wordmark region, including the emblem.

## Provider availability, privacy and cost

`GROQ_API_KEY_BACKUP` is optional from GitHub Actions through secret provisioning to the Worker. The primary is used normally. Only an unambiguous HTTP 401 authentication failure activates the standby credential. A 429 organization quota, model-access failure, outage or uncertain network request never rotates keys. Both supplied keys authenticated against Groq's model endpoint in the release access check; failover routing is covered separately by mocked authentication failures. A standby key in the same organization adds no quota.

The current owner-testing release disables application budgets with `AI_APP_LIMITS_ENABLED=false` behind owner authentication; no quota-store access or estimate-based rejection occurs in that mode. See [owner testing](OWNER-TESTING.md). When re-enabled with `true`, application budgets are configurable through bounded Worker variables: `AI_DAILY_REQUESTS` (default 80, ceiling 1000), `AI_DAILY_TOKENS` (100000, ceiling 180000), `AI_SESSION_DAY` (30, ceiling 200), `AI_SESSION_MINUTE` (4, ceiling 10), `AI_NETWORK_DAY` (60, ceiling 500), `AI_NETWORK_MINUTE` (12, ceiling 20), and `AI_GLOBAL_MINUTE_TOKENS` (7500, ceiling 7500). Rolling reservations pace application traffic within the verified free 8000-token/minute model window, reconcile actual usage and carry live minute holds across a UTC day boundary. A separate daily attempt ceiling prevents rejected/refunded calls from growing abuse state indefinitely. Reservations reconcile actual usage; confirmed rejections refund daily billable allowances while retaining abuse-attempt limits. Uncertain calls keep their bounded hold. Submission identities remain recorded after reconciliation, and provider cooldowns respect Retry-After/reset information without automatic retries. All application daily limits reset at midnight UTC without wiping valid records. Groq token headers describe per-minute capacity, not an invented daily token balance.

Optional image AI uses the existing server-side Workers AI binding with `@cf/black-forest-labs/flux-2-klein-4b`, an Apache-2.0 model supporting real reference-image editing. Output is bounded to 512 × 512, one input is smaller than 512 × 512, and a separate allowance limits shared usage to eight successful or uncertain requests per UTC day and two per session, with a separate ceiling of 24 total attempts. Whole-page document images are blocked from cloud submission. A separate per-document image consent displays the selected image that would be sent. Local/upload tools remain available on every provider failure. No AI Gateway credits, paid fallback, billing writes or automatic top-ups are used. Deployment verifies a free Cloudflare account before activation.

Official references checked for this release: [Groq organization limits and header meanings](https://console.groq.com/docs/rate-limits), [Workers AI image input and binding example](https://developers.cloudflare.com/changelog/post/2026-01-15-flux-2-klein-4b-workers-ai/), [Workers AI free allocation and model pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [model license and limitations](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B), and [provider error codes](https://developers.cloudflare.com/workers-ai/platform/errors/).

## Verification boundaries

Unit tests and mock APIs cover state transitions, routing, accounting and failures; they are not live-provider evidence. Real browser tests capture downloads and compare their SHA-256 with the actual preview bytes. Independent PDF.js and Poppler/pdfplumber checks cover complete text, original removal, point sizes/positions, page geometry, links, strict numeric regions, planned reflow/image regions, alpha, other shared occurrences and unchanged supporting pages. Full pages and enlarged affected regions are inspected visually.

Private fixtures, derivatives and evidence stay in ignored local storage and are never CI inputs or public artifacts. The local private acceptance run blocked outbound/provider requests. Free Workers AI access was verified independently using an invented red-square input and a blue-square edit, with a semantic output check; its temporary authenticated probe Worker was removed afterward. Production browser/provider evidence is recorded separately at release time.
